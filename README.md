# Trader Research

Локальный терминал для исследования акций MOEX: цена, SMA, RSI, MACD, Bollinger Bands, скринер и RSS-новости. Интерфейс работает без внешних CDN и библиотек JavaScript.

## Запуск в VS Code

Откройте папку проекта, затем встроенный терминал. Нужен Python 3.12. Не используйте закоммиченный каталог `venv`: он содержит файлы другой машины.

**Windows / PowerShell:**

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt -r requirements-lock.txt
.venv\Scripts\python backend/app.py
```

**macOS / Linux:**

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt -r requirements-lock.txt
.venv/bin/python backend/app.py
```

Откройте `http://127.0.0.1:5001` в браузере. В VS Code: **Python: Select Interpreter → .venv**. Для остановки сервера нажмите Ctrl+C. Это сервер разработки, не production-развёртывание.

Необязательные переменные: `TRADER_HOST` (по умолчанию `127.0.0.1`), `TRADER_PORT` (`5001`), `TRADER_DB_PATH`, `TRADER_MODELS_DIR`. По умолчанию изменяемая база и новые модели находятся в игнорируемом каталоге `.runtime`. При первом запуске база копируется из исходной `trading_data.db`. Ключи API для публичных MOEX ISS и RSS не нужны.

Версии проверенного окружения зафиксированы в `requirements-lock.txt`; ограничения проекта — в `requirements.txt`. Проверено на Linux / Python 3.12. Команды Windows приведены для локального запуска, но здесь Windows не тестировалась.

## Как читать результаты

- Оценка от −100 до +100 — среднее трёх групп: тренд, импульс, возврат к среднему. Коррелирующие SMA не получают два полных голоса. Это не вероятность и не ожидаемая доходность.
- Объём описывает активность, а не направление цены.
- При отсутствии совместимой ML-модели показаны правила; вероятность отсутствует. Модель классифицирует рост более 0.5% через 8 **свечей**, а не обязательно часов. Сценарий HOLD означает отсутствие сигнала BUY, а не доказанный прогноз бокового рынка.
- Для ML используются хронологическое разделение и разрыв на длину горизонта. Сохраняются признаки, таймфрейм, горизонт и контрольные метрики. Старые модели без метаданных не подхватываются автоматически. Вероятности пока не откалиброваны.
- Новости анализируются локальными словарями и финансовыми фразами. Привязка учитывает названия компаний, отраслевые и общерыночные события. Правила ошибаются в сложном контексте. Новости **не входят** в признаки ML.
- Рабочие тикеры Яндекса и Т-Технологий — `YDEX` и `T`; устаревшие обозначения распознаются в новостях.
- Используются завершённые свечи. Даты свечей — время Москвы. Изменение цены считается к предыдущей свече выбранного таймфрейма.
- Свежесть и источник показаны явно: MOEX, сохранённая база или архив. Во время выходных/ночных перерывов консервативный индикатор свежести может показывать устаревание. Полный торговый календарь ещё не подключён.

Котировки кэшируются на 5 минут на тикер/таймфрейм, новости — на 15 минут. Обновление в интерфейсе запрашивает текущий серверный кэш. Скринер использует до четырёх параллельных запросов; отдельного фонового сборщика пока нет. Ошибки получения данных не заменяются вымышленными значениями.

## Проверки

Используйте Python из `.venv` вместо `python` в следующих командах, если окружение не активировано:

```bash
python -m unittest discover -s tests -v
python backend/backtest.py --csv data/SBER.csv --cost-bps 10
```

Тесты используют временную базу и подменённые внешние ответы. Бэктест проверяет правила на предоставленной истории: решение после закрытия свечи, исполнение на следующем открытии, комиссии/проскальзывание через `cost-bps` на сторону. Он сравнивает результат с buy-and-hold, считает просадку и долю прибыльных сделок. Это не независимая проверка прибыльности ML. Исторические CSV могут не учитывать дивиденды и корпоративные действия. Для реального исследования нужны проверенная история, walk-forward-проверка на нескольких периодах и инструментах, а также реалистичные издержки.

## Обучение модели

```bash
python backend/train.py --ticker SBER --csv data/SBER.csv --timeframe 1d --horizon 8
```

Для часовой модели укажите `--timeframe 1h` и CSV с часовыми свечами. Новый артефакт появится в `.runtime/models`; API автоматически использует модель соответствующего тикера, таймфрейма и горизонта. Перед использованием проверьте качество своей истории. Обучение на предоставленном CSV не заменяет независимый тест на будущих данных. Скрипт сохраняет accuracy, precision/recall BUY, Brier score и границы train/test.

## Структура

- `backend/app.py` — Flask API и маршруты.
- `backend/market.py` — получение, кэш и статус котировок.
- `backend/analytics.py`, `signal_analyzer.py` — единые расчёты и сценарии.
- `backend/ml_model.py` — обучение и загрузка совместимых моделей.
- `backend/news_analyzer.py` — RSS, компании и тональность.
- `frontend/` — адаптивный интерфейс, графики Canvas, безопасный вывод внешнего текста через DOM.
- `tests/` — регрессионные тесты.

Сеть должна разрешать `iss.moex.com` и RSS-источники из `backend/news_analyzer.py`. При недоступной сети приложение показывает доступную историю и предупреждение. Пустая лента не доказывает отсутствие новостей.

## Работа с Git

Файл `.gitignore` исключает новые локальные окружения, секреты и рабочие данные. В исходной версии проекта уже отслеживаются `.env`, `venv`, байткод и служебные файлы: `.gitignore` не удаляет их из истории. Перед публикацией репозитория отдельно проверьте `.env`; если он содержал настоящие ключи, замените их и очистите историю. Не загружайте чужие pickle-модели: их загрузка выполняет Python-код.

## Изменения API

Новый интерфейс и backend обновляются вместе. `/api/news` и `/api/ticker/<ticker>/news` теперь возвращают объект `{items, stale, updated_at, method}`, а не голый массив. Карточка акции возвращает `analysis`, `risk`, `data_status` и единый `ai_prediction`. ML-проценты имеют диапазон 0–100; для правил вероятность равна `null`. Скринер сохраняет строку с `error`, если по акции нет данных, вместо молчаливого исключения акции.
